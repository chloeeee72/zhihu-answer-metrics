# 发布与仓库设置清单

## 1. 仓库元数据

在 GitHub 仓库页面右上角 About 齿轮里填：

**Description**（建议，英文以覆盖更广搜索）：

```
Word count and reading time for every answer on a Zhihu question page. Unofficial Manifest V3 extension + UserScript. No permissions, no network, no data collection.
```

**Topics**（最多 20 个，建议全填）：

```
zhihu
userscript
tampermonkey
browser-extension
chrome-extension
edge-extension
manifest-v3
javascript
word-count
reading-time
productivity
privacy-friendly
no-tracking
chinese
```

**勾选**：Releases、Issues、Discussions（可选）。

## 2. 仓库地址

```
git@github.com:chloeeee72/zhihu-answer-metrics.git
```

已写入以下位置，无需再改：

| 文件 | 位置 |
| --- | --- |
| `package.json` | `repository.url` |
| `tools/build-userscript.mjs` | `REPO` / `REPO_RAW` 常量 → UserScript 的 `@namespace`、`@homepageURL`、`@supportURL`、`@downloadURL`、`@updateURL` |
| `README.md` | UserScript 安装 URL |
| `.github/workflows/release.yml` | 无需仓库地址，CI 自动注入 |

改了 `tools/build-userscript.mjs` 里的 `REPO` 常量后必须重新生成 UserScript：

```bash
node tools/build-userscript.mjs
```

否则脚本管理器的自动更新 URL 会指向错误的地址。

## 3. 隐私政策托管（GitHub Pages）

`docs/` 已按 GitHub Pages 的发布要求组织好，只剩在网页上开一下开关：

1. 仓库 **Settings → Pages**
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 **`/docs`**，Save
4. 等一两分钟，三个地址可用：

```
https://chloeeee72.github.io/zhihu-answer-metrics/            索引页
https://chloeeee72.github.io/zhihu-answer-metrics/privacy.html 隐私政策（填进商店 Privacy 页）
```

目录内容：

| 文件 | 作用 |
| --- | --- |
| `docs/index.html` | 站点索引页，链到仓库、Release、隐私政策 |
| `docs/privacy.html` | **隐私政策规范版**，商店 Privacy 页填这个 URL |
| `docs/icon300.png` | 索引页用的图标，从 `extension/icons/` 复制 |
| `docs/.nojekyll` | 关掉 Jekyll 处理，避免静态文件被改写 |
| `docs/仓库与发布清单.md` | 本文件，发布操作手册 |

`extension/demo/privacy.html` 不是第二份政策，而是一个重定向壳，由 `node tools/pack.mjs`
自动生成，指向 Pages 上的规范版。`node tools/pack.mjs --check` 会校验它没有过期，
CI 也跑这一步，所以两处不会漂移。

也可以只声明「本扩展不收集任何数据」而不填 URL，但填了更稳，审核员也更省事。

## 4. 打 tag 发版

`.github/workflows/release.yml` 会在推 `v*` tag 时：

1. 跑 `extension/tools/run-logic-check.js`（逻辑比对）
2. 跑 `tools/build-userscript.mjs --check`（生成物是否最新，漂移则失败）
3. 跑 `tools/pack.mjs` 打 zip
4. 把 zip 和 `.user.js` 一起挂到 GitHub Release

```bash
# 1. 改 extension/manifest.json 的 version（唯一版本来源）
# 2. 同步生成 UserScript
node tools/build-userscript.mjs
# 3. 提交打 tag
git commit -am "chore: release 4.3.0"
git tag v4.3.0
git push origin main --tags
```

## 5. 上架商店（Edge / Chrome）

| 项 | 值 |
| --- | --- |
| 包 | GitHub Release 里的 `zhihu-answer-metrics-4.3.0.zip`，或本地 `node tools/pack.mjs` 产出的 `store-package.zip` |
| 名称 | `知乎回答字数统计 \| 阅读时间估算`（manifest 里，只读不可改） |
| 分类 | Productivity |
| 权限理由 | 见 `extension/store/商店文案.md` |
| 认证备注 | 见 `extension/store/认证备注.md` |
| 图标 300×300 | `extension/icons/icon300.png` |
| 截图 | **待补**：1280×800 或 640×400，截真实知乎问题页，需看清统计条 |

商店侧还有两件仓库无法代办的：**支持邮箱**要能在 Partner Center 填并能收信；
**开发者身份验证**必须先过，否则提交按钮不可用。

## 6. 提交前自查

```bash
node tools/build-userscript.mjs --check                      # 生成物同步
node extension/tools/run-logic-check.js                      # 扩展逻辑
node extension/tools/run-logic-check.js userscript/zhihu-answer-metrics.user.js  # UserScript 逻辑
node tools/pack.mjs                                          # 打包
grep -rn "<owner>" . --include="*.md" --include="*.mjs" --include="*.json"   # 应为空
```
